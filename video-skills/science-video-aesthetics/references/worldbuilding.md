# 场景化：把知识放进一个活的世界里讲

**这是本 skill 最重要的一份文档。** 风格解决"长什么样"，这份解决"讲给谁看、在哪里讲"。

## 核心区别：白板 vs 世界

同一个主题（霍特林定律），两种做法：

| | 白板式（要避免） | 世界式（要做到） |
|---|---|---|
| 画面骨架 | 固定版式：顶部标题 + 中间示意图 + 下方数据卡 + 底部字幕，每一屏都一样 | 全屏就是一个地方：一片沙滩、一条街、一座城。没有常驻的标题栏和数据面板 |
| 模型元素 | 图标：小卡车图标、一排小人符号、一条彩色数轴 | 实物：俯视的冰淇淋车（车顶有巨大冰淇淋球）、躺在毛巾上晒太阳的游客、遮阳伞 |
| 数据 | 画在世界之外：分数卡、百分比面板、坐标轴 | 长在世界里面：卷尺躺在沙滩上、沙子被染成两种颜色、每个游客头顶冒出所选车的颜色徽章、旗子插在分界线上 |
| 静止时 | 画面完全不动，等下一句字幕 | 浪在拍岸、海面反光闪烁、伞在微微转、徽章上下浮动、海鸥叫 |
| 角色 | "左车 A""右车 B" | "草莓车""薄荷车"，有想法（气泡："要是我往中间挪一点……？""那我也挪！"），有情绪（"亏了亏了！"） |
| 镜头 | 固定机位 | 推近一个游客看他算距离，跟着车移动，两车相撞时震一下，揭晓时拉远 |
| 声音 | BGM + 少量提示音 | BGM + 环境声底（海浪、街道人声）+ 每个可见变化都有声音（每个游客改选都"啵"一声） |
| 观众感受 | 在听课 | 在看一个故事，顺便懂了 |

**白板式不是错，它准确、清楚。但短视频观众是被世界留住的，不是被图表留住的。**
沙滩、海浪、海鸥对论证没有任何必要——这恰恰是重点：它们让论证变得想看。

## 第一步：写"世界设定"（编码前必做，写进 `scenes.py` 顶部注释）

### 1. 选舞台
问：这个模型**在现实中最自然发生在哪里**？优先顺序：
1. 原论文 / 经典教科书里的场景（霍特林原文就是沙滩冰淇淋车；囚徒困境就是审讯室；三枪手就是西部决斗）。
2. 观众生活里最熟悉的场景（奶茶街、地铁站、超市排队）。
3. 能把抽象维度变成物理空间的场景（一维模型 → 一条海岸线 / 一条街；二维 → 俯视城市；时间 → 一天的日照）。

舞台要**能俯瞰或横向铺开整个模型**，这样整个论证都能在一个镜头里发生。

### 2. 填映射表：每个抽象概念 → 世界里的一个实物
必须一项不漏，**不允许出现"世界之外"的图表元素**（字幕和少量计分条除外）：

| 抽象概念 | 世界里的实物 | 怎么动 / 怎么变 |
|---|---|---|
| 一维市场 [0,1] | 1000 米长的海岸线 | 浪在上沿拍打 |
| 均匀分布的消费者 | 66 组晒太阳的游客（伞、毛巾、肤色、朝向随机） | 呼吸般微动 |
| 厂商位置 | 两辆俯视冰淇淋车 | 开动时扬起沙尘、车身颤动 |
| 距离 | 一条黄色卷尺躺在沙滩上，开场时展开 | 关键刻度变红 |
| 消费者选择 | 每人头顶一个冰淇淋徽章，颜色 = 所选车 | 分界线扫过时放大弹跳 + "啵" |
| 市场份额 | 沙子被染成珊瑚色 / 薄荷色两块，边界插一面小黄旗 | 随车移动连续滑动 |
| 份额数字 | 顶部一条拔河式计分条（唯一的"面板"） | 数字实时变化 |
| 时间推进 | 早晨 → 正午 → 黄昏的调色和影子方向 | 结尾日落 = 故事终点 |

映射写不出来的概念，说明舞台选错了，换舞台。

### 3. 给角色起名、给动机
- 竞争者 / 粒子 / 变量都要有名字和颜色，全片一致（字幕里也用同一颜色）。
- 关键决策用**内心独白气泡**说出来，而不是旁白解释："要是我往中间挪一点……？"比"厂商有向中心移动的激励"好十倍。
- 让角色**试错并吃亏**：均衡的稳定性，用"有人试着离开→地盘被吃→灰溜溜回来"来演，而不是用一句"偏离会降低收益"。

### 4. 列出环境生命层（≥ 4 个与论证无关、但一直在动的东西）
例：海浪拍岸（6.5 秒周期）、远处的涌浪线、海面闪光、遮阳伞微转、棕榈叶摆动、徽章浮动、云飘、排队的人轻轻晃。
规则：**任何一帧都不能完全静止**；字幕停留时世界照样在动。

### 5. 列出细节密度（奖励暂停截图的观众）
几十个实例 + 每个都有随机变化（固定种子）：不同颜色的伞、条纹毛巾、肤色和发色、沙滩上的贝壳和脚印、街边"旺铺招租"。
**单调的扁平矢量显得廉价，是因为空，不是因为扁平。**同样的扁平矢量，密度和变化够了，就会显得精致。

## 第二步：用世界讲故事的手法

- **钩子 = 世界的结局**：开头直接给结果（两家奶茶店挤在街中间、两头"旺铺招租"；两辆车贴在沙滩中央），再"倒带"回到起点。
- **一个世界贯穿全片**：开头、推导、结尾都在同一个地方；结尾回到同一片沙滩，但已是黄昏。光线变化本身就是叙事弧线。
- **现实例子 = 换一个世界，保留同一套颜色**：奶茶街、选民分布、手机外形，都沿用珊瑚 / 薄荷两色，观众一眼就把它们和沙滩模型对上。
- **镜头是叙述者**：
  - 讲个体时推近（一个游客到两辆车各有多远）；
  - 讲整体时拉远（分界线扫过整片沙滩）；
  - 关键节拍用冲击（两车相撞：震动 + 闷响）；
  - 节奏加快时镜头逐步推近（"你挪一步，我挪一步……"每步更快、镜头更近）。
- **转场也属于这个世界**：用沙滩毛巾般的彩色条纹斜扫，而不是通用的淡入淡出。
- **盖章 / 招牌词要做成世界里的物件**：红色印章"纳什均衡"砸在两辆车上方，而不是一行标题。

## 第三步：声音景观

1. **环境声底**跟着场景切换：沙滩 = 滤波噪声海浪（起伏周期和画面浪潮用同一个公式）+ 偶尔成对的海鸥；街道 = 带通噪声人声。切场景时声底跟着切。
2. **每个可见变化都有声音**，按"谁变了"自动生成：遍历每帧每个游客的选择，变了就在他的屏幕位置放一个"啵"（声像随 x 坐标），音高区分两家。
3. **角色动作有拟音**：车开动 = 低频锯齿发动机 + 沙地轮胎噪声；登场按两声喇叭；赚到 = 收银机"叮"；亏了 = 下行蜂鸣。
4. 环境声压在 BGM 下面（增益约 0.1），只当空气，不抢戏。

## look-dev 时的"白板味"自检

主视觉联系表出来后逐条问，**任意一条为"是"就重做**：
- [ ] 画面上有常驻的标题栏 / 小标题 / 数据卡片区吗？（字幕和一条计分条以外）
- [ ] 模型元素是图标、符号、小人剪影，而不是有细节的实物吗？
- [ ] 把字幕遮住，这一帧还看得出是"在什么地方发生了什么事"吗？（看不出 = 白板）
- [ ] 静止 2 秒时，画面上有至少 4 处在动吗？
- [ ] 背景里有 30 个以上带随机变化的实例吗？
- [ ] 数据（距离、份额、分界）是画在世界里的物件上，还是画在坐标轴 / 面板上？
- [ ] 角色有名字、有气泡台词、有一次"吃亏"吗？

## 世界式不等于牺牲准确

白板式的长处要保留：
- 关键数字由代码算出（份额、距离、平均步行距离），画面、字幕、计分条一致；
- 假设写在画面上（价格相同、口味相同、游客均匀）；
- 必要时在世界之上叠一张卡片做结论（如"霍特林定律"卡片、"125 m → 250 m"对比卡），但卡片出现几秒就收起，世界始终在后面活着。

## 参考实现

`assets/examples/hotelling/`：本文所有例子的完整源码（pycairo 俯视沙滩 + 街景 + 选民分布 + 手机演化，约 1500 行）。
- `world.py`：怎么用几十行画出俯视遮阳伞、躺着的人、棕榈树、冰淇淋车、海浪和泡沫线、卷尺、HSL 染色地盘。
- `story.py`：Track 关键帧轨道（车位置 / 镜头）、字幕表、气泡、浮动增减数字、日夜调色、条纹转场。
- `street.py`：正视街景（招牌、条纹遮阳篷、排队人群）、选民直方图、手机形态插值。
- `audio.py`：海浪 / 海鸥 / 发动机 / 喇叭 / 收银机等音效合成，以及"每个游客改选就啵一声"的自动音效。

它是独立的 pycairo 项目，不依赖任何工具包。读它是为了学**思路和画法**，外观适合就沿用，不适合就换，但都要做到"一个活的世界"。
