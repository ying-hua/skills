# 已知技术问题（每条一行：症状 → 解决办法）

## 渲染
- **GPU 着色器出现 NaN**：一个坏像素会被 mip 泛光放大成闪烁的黑方块。重着色器的输出都要加 `if(any(isnan(c))||any(isinf(c))) c=vec3(0.);`（`vk_gl` 的 resolve 已内置），每个分段都要跑 `vk_scan.py spikes`。
- **多重采样噪点每帧乱爬**：每帧使用相同的抖动序列（`vk_gl` 已这样做）。
- **重着色器在 Windows 上触发 GPU TDR 重置**：使用 `GL(tiles=4)` 分条渲染。
- **泛光把画面冲白**：`vk_core` 的泛光叠加了多级模糊，发光层亮度控制在约 0.3–0.6，大面积区域不要画进 `cv.g`，画在底层。
- **轮廓光用整条路径描边，内部边缘也发光**：在发光层先描边，再用 OPERATOR_SOURCE 黑色填充路径内部。
- **镜头平移或缩放露出画布边缘**：保持 `W/2/zoom ≤ cx ≤ W − W/2/zoom`，或把背景画得比画面大。
- **慢动作、倒带等时间重映射**：倒带结束后的状态里，瞬时物体不能再绘制，否则会冻结在画面上。
- **pycairo 的 `ImageSurface` 不能挂属性**：用模块级列表保持 numpy 缓冲区存活（`vk_core` 的 `_KEEP`），或直接写入 `surface.get_data()`。
- **缩放从 0 开始时 cairo 报 out of memory**：`scale(0)` 让矩阵不可逆，绘制前判断 `scale < 1e-3` 直接跳过。
- **跨很多数量级的连续缩放（10⁰→10²⁷ 米）**：坐标全部用 float64 在 Python 里投影成屏幕像素再交给 cairo（cairo 是 24.8 定点数，超过约 800 万像素就出错）；半径上亿像素的圆只画可见的一段弧再在圆内闭合。
- **大纹理被放大几十倍变成模糊色块**：一张纹理只在"视野宽度≈纹理覆盖范围的 1/2～1 倍"时清晰。放大段改用每帧低分辨率程序化计算（如 384×216 网格算密度场再放大），或在下一级纹理接管前淡出。
- **相邻两个全屏插画场景交叉淡化时露出底下的场景**：两个窗口在交界处都小于 1。给整段插画再垫一层不透明背景（取各窗口的并集），或让前一段的窗口延后结束。
- **缓存纹理用 `to_surface` 生成后又在每帧清空 `_KEEP`**：缓冲区被释放，画面变成垃圾。长期缓存的纹理用自己的模块级列表保存 numpy 缓冲区，只把逐帧临时贴图放进 `_KEEP`。
- **数字字体（Rubik 等）没有汉字**：混排的"250 米"会丢掉"米"，含汉字的文字用中文字体。
- **`add_text(font=等宽/数字/西文斜体)` 里出现字体没有的字（汉字、U+2212 减号 −、√ ≈ → ∞）显示成方框**：`vk_core` 用 `has_glyph` 逐字检测，按“指定字体 → 拉丁/中文默认 → `SYMBOL_FALLBACK`”找第一个有字形的字体。项目里的 `vk_core.py` 是建项目时复制的副本，kit 修复后要重新复制，否则还是旧行为。交付前对全片用到的文字跑一遍 `missing_glyphs(markup, weight, sans, font)`。
- **公式写成纯文本（`G_μν`、`x^2`）会把下划线、脱字符原样画出来**：用 `add_math(cv, r'G_{\mu
u} = rac{8\pi G}{c^4} T_{\mu
u}', x, y, size)`（matplotlib mathtext，无需安装 TeX）；希腊字母 ν（nu）不要用拉丁字母 v 代替。

- **每帧调用 `add_math` 让渲染变慢好几倍**：mathtext 排一次公式约 50–150 ms。现在 `add_math` 按（公式, 字号, 颜色, 字体集）缓存渲染结果（不受 `_KEEP.clear()` 影响）；项目里复制的旧 `vk_core.py` 要重新复制。公式的字墨框记在 `cv.math_boxes`，`text_in_zones` 也会检查它。
- **`add_text` 的字压在后画的面板、底部渐变条上面（滚动表格的行号跑进字幕区、标签透出遮罩）**：文字在 `finish` 里最后合成，永远在 `cv.c`/`cv.g` 上所有图形之上，画在底层的面板挡不住它。按文字的屏幕位置自己乘一个淡出系数（例如进入面板上沿以下 40 px 内淡到 0），或把这类大量小标签改用 `world_text` 画在底层。
- **几十圈同心环 / 粒子环一层套一层收向中心（“无穷隧道”、望远镜视角），中心糊成一团白**：环半径按等比 `r0·q^L` 缩小（q≈0.8），只画半径大于几像素的前十几层，每圈的点数和点的大小随半径缩小；中心的光点亮度单独控制，压字幕时调暗。
- **画完某个元素后，后面的东西全都“消失”了（不报错，只是没画出来），或越画越偏**：绘制函数里 `ctx.save()` 比 `ctx.restore()` 多一次，变换（平移/缩放）一路累加，后面的图形都被画到画面外。每个自绘函数的 save/restore 要成对；调试时在函数前后打印 `ctx.get_matrix()`，前后应相同。
- **音效的铃声、拨弦和 BGM 的调不合，听着“打架”**：`python vk_bgm.py <bgm>` 会输出 `KEY`（估计的调式）和一组五声音阶 MIDI 音符，有音高的音效只从这组音里取。
- **圆、折线的开头多出一条长长的直线，连到画面外某处**：`show_text()` 之后 cairo 保留当前点（`save/restore` 不会清掉路径），下一次 `arc()` 会从那个点连一条线过来。逐字 `show_text` 之后调用 `ctx.new_path()`；`polyline` 已自带。
- **分段并行渲染后，各分段之间纹理（纸、沙、噪声）一跳一跳**：Python 的 `hash(str)` 每个进程随机，拿它当随机种子，每个工作进程生成的纹理都不一样。种子用固定数字或 `sum(map(ord, name))`。
- **`add_text` 的文字不跟随 `set_cam`**：文字在 `finish` 里按屏幕坐标合成，镜头缩放/平移时会留在原位。要么自己把世界坐标换算成屏幕坐标（`W/2 + (x - cx) * zoom`），要么在镜头动起来前把这些标签淡出。
- **整场景交叉淡化**：用 `vk_core.group(cv, lambda cv: draw_scene(cv), a)`（在 `cv.c` 和 `cv.g` 上同时 `push_group` → 画 → `paint_with_alpha(a)`，新增的 `cv.texts` alpha 乘 a）；最底下那个场景保持不透明，否则交界处会透出黑底。
- **缩放中的重复点阵/网格出现摩尔纹、或逐点绘制太慢**：画一个单元的小 tile，用 `cairo.SurfacePattern` + `EXTEND_REPEAT` + `FILTER_GOOD`（正确的缩小滤波）和缩放矩阵一次 `paint`；间距小于约 4 px 时再淡入一层均匀的平均色。
- **2D 缩放镜头无缝接到 GL 3D 场景**：让 GL 相机正上方俯视，视野宽度 F 对应距离 `d = F / (2·tan(fov/2)·W/H)`（`camRay` 按高度归一化）；`look_at` 正俯视时 up 向量退化，给相机位置加一点 +z 偏移（`(0, h, 0.02·d)`）使屏幕右 = +x、屏幕下 = +z，与 2D 坐标对齐，交叉淡化 0.5 s 后再把相机移到斜视角度。

- **浅色背景（纸张、白底）上用发光层，亮的东西被冲成一片白**：`cv.g` 是加色的，在亮底上只会过曝。浅底场景把"发光"画在底层（暖色径向渐变 + 稍深的线色），发光层只留很弱的点缀。
- **逐字打出的一行字，第 0 帧只出现半行、整体偏到一侧**：把这一行的出现时间设成负数，让第 0 帧已经是完整居中的一行，后面的行再逐字打出。
- **把 uint8 图（0–255）交给旧版 `to_surface` / `to_surface_rgba`，整片变成白色或奶油色**：旧版默认输入是 0–1 的浮点，内部再乘 255 后饱和。现在两者遇到 uint8 会先除以 255；项目里复制的旧 `vk_core.py` 要重新复制，或自己先 `.astype(np.float32) / 255`。
- **封面 / 标题压在大片发光点（地图上的疫点、城市灯光、星团）上看不清，底下垫了暗色带也没用**：暗色带画在底层，发光层 `cv.g` 的泛光是在 `finish` 里后加上去的，不会被底层的带子压暗。文字区域里的发光点在画的时候就把发光强度乘一个随到文字距离变化的系数（例如 0.3→1），底层的暗带只负责压暗底图。
- **世界地图要在缩放 10 倍的过程中一直是清楚的“点阵地图”**：每帧用 `cv2.fillPoly(..., LINE_AA, shift=4)` 按当前镜头把陆地多边形画成蒙版（1080p 约 10–20 ms），再乘 `lattice_dots`（点阵固定在地图坐标上、分级交叉淡化，屏幕上点距和点大小不变）。只填色不描边，就不会画出国界；中国用的地图另见项目里的合规要求。
- **缓存纹理每帧都要用**：`to_surface(img, persist=True)` 把缓冲区放进 `_PERSIST`，不会被 `_KEEP.clear()` 释放。
- **封面文字避让区（平台角标、点赞数会盖住的角落）**：`finish` 之后看 `cv.text_boxes`，或 `text_in_zones(cv, [(0, 0, .5, .25), (0, .87, .5, 1)])` 返回落进区域的文字；不要用"有字版 − 无字版"逐像素比较，`glow=` 光晕会带出 1/255 级的差。
- **用 CIE 配色函数直接把单色光换成 sRGB 画彩虹，红端变粉、蓝绿段发灰**：单色光大都在 sRGB 色域外，减最小值去饱和后颜色不像彩虹。画光谱条、彩虹用 `vk_spectral.wavelength_rgb`；算物体颜色（反射光谱）才走 `spectrum_xyz → xyz_to_linear`。
- **同一场景换“眼睛”（狗、蜜蜂、色盲）重画**：每种材质存一条反射光谱，按观察者算出一套调色板，同一个绘制函数传不同调色板；分屏或圆形透镜对比用 `ctx.clip()` 分区各画一遍，比逐像素换色便宜得多。

- **大面积“白光”（刺眼的天空、闪白）看起来是灰的**：`finish` 的高光柔肩让输出最高只到约 1/`cv.shoulder`（默认 1.2 → 约 0.83，即 212/255）。需要真正的白时把 `cv.shoulder` 调低（如 0.15），或在成帧后按亮度做局部提亮；暗角也会把四角压灰，同时降低 `cv.vignette`。
- **把整张纹理（天空、彩色图）画进发光层 `cv.g`，前景剪影也跟着发光**：泛光不知道遮挡，后画在底层的山、树、人物会被叠上一层彩色辉光。整幅纹理只画在底层（`OPERATOR_ADD` 也行），发光层只放点光源，或先用前景蒙版把发光层对应区域清零。
- **成千上万颗星星 / 粒子逐个 `arc`**：用 `splat_points(img, xs, ys, flux, col, sigma)` 一次性按亚像素双线性沉积再模糊，再 `to_surface` 贴上；最亮的几十颗再单独画光晕。
- **滚动的地面 / 透视平面（`cv2.remap(..., BORDER_WRAP)`、`EXTEND_REPEAT`）中间出现一条笔直的接缝**：纹理本身左右、上下不相接（`fbm`、普通距离变换的细胞纹理）。细胞类纹理（日面米粒、植物细胞、泡沫）用 `worley(h, w, spacing, tile=True)`（种子放在环面上），噪声用 `pnoise`；平铺前先在一个像素的位移下比较首尾行列。
- **每帧 `splat_points` 几十万个点很慢**：旧版用 `np.add.at`；现在改为 `np.bincount` 累加（同样结果，约快 10 倍）。项目里复制的旧 `vk_core.py` 需要重新复制。
- **经纬贴图（等距圆柱）贴到球上，±180° 经线出现一条接缝，两极出现放射状条纹**：普通 `fbm` 左右不相接，改用 `pnoise`（x 方向首尾相接）；纹理细节在极点会挤成放射状，纬度约 75° 以上把云层、噪声淡出。
- **几百条起点几乎相同的轨迹（集合预报、粒子团）叠在发光层上冲成一团白**：发光层是加色的，N 条重合的线亮 N 倍。尾迹画在底层（OVER 叠加，重合再多也只饱和到本色），发光层只放头部，头部亮度按 `1/(1+k·e^(−离散度))` 缩放；散开以后自然恢复亮度。
- **成排的密集点光源（灯阵、观众席、城市灯光）糊成连续的光带**：屏幕上相邻两点间距小于约 2 px 时就看不出"颗颗分明"。按相机距离估算点距，保持 4–6 px 以上；全分辨率在底层 `splat_points` 画清晰小点，发光层再画一遍做光晕。
- **想让一台机器、一张桌面“躺”在镜头前（透视倾斜），cairo 只有仿射变换**：先在离屏层上平铺着画，再用 `tilt_homography` + `warp_layer` 透视贴上；层上的字用 `world_text`（`add_text` 在 finish 里按屏幕坐标合成，不会跟着变形）；近景放大时把 `scale` 调到 1.3–1.5，否则纹理被放大发糊。
- **`cv2.remap` 只采样一部分像素（圆盘里的地球像素、某块区域）时把坐标排成 (N, 1) 的映射，N 超过 32767 就报错或出错**：映射的两个维度都必须小于 32767。用 `sample_points(img, mx, my)`，它把点折成每行 2048 个再 remap。
- **`ss` / `clamp01` 传入 numpy 数组报 “truth value of an array is ambiguous”**：旧版只支持标量；现在两者都支持数组。项目里复制的旧 `vk_core.py` 要重新复制。
- **按国家多边形逐个 `fillPoly(LINE_AA)` 画陆地，相邻国家的公共边上留下一圈半透明细缝（看起来就是国界线）**：后画的多边形的抗锯齿边会覆盖先画的。所有陆地在 2 倍分辨率上不开抗锯齿填成一张并集蒙版，再 `INTER_AREA` 缩小一半当覆盖率；分块（板块、大洲）的编号另存一张最近邻 id 图，并向海里扩几个像素，免得抗锯齿边被切掉。
- **板块 / 大陆在球面上移动、拼合（大陆漂移、地图拼图）**：每块用 `fit_rotation(src, dst)` 从几对“现在的位置 → 拼合时的位置”经纬点拟合一个旋转，`rot_power(M, k)` 按 k 在 0…1 间匀速插值；逐像素绘制时对屏幕像素的经纬度做逆旋转（`rotate_lonlat(M.T, …)`）再去现在的纹理里采样，先用每块的中心和角半径筛掉不相关的像素。
- **极光用 sin² 做竖向光线，整排等距的尖峰看起来像栅栏或一排松树**：改成两三条随时间起伏的柔和光带（下沿陡、向上指数衰减），只叠很弱、非周期的亮度起伏。
- **逐帧画网格线 / 竖条时偶尔有一帧整体变暗、网格消失（单帧闪烁，`vk_scan spikes` 能抓到）**：`gl[:, max(0, xi - 1):xi + 1] = 1` 在线条坐标取整成 -2 时变成 `gl[:, 0:-1]`，负数终点让整张图都被涂上。切片两端都要夹到 0 以上：`gl[:, max(0, xi - 1):max(0, xi + 1)]`；镜头缓慢平移时，网格线恰好压在画面边缘的那一帧才会出现。

## 性能与运维
- **16 GB 内存开 10 个以上进程会 MemoryError**：每个进程缓存 0.6–1 GB，最多开 5 个；同机还有其他渲染任务时降到 3 个或暂停，失败的分段单独补渲。GPU 渲染只开 1 个。
- **工作进程里 BLAS 线程过多**：设置 `OMP_NUM_THREADS=1`（`vk_render` 已设置）。
- **agent 的 shell 工具通常有超时**：长时间渲染放到后台，用 `tail` 轮询日志。
- **shell heredoc 里嵌套引号会破坏多文件写入**：用 agent 的文件写入工具创建文件。
- **分段渲染中途被杀或崩溃**：分段先写 `.tmp` 再改名，重跑会自动续渲；要强制重做就删掉对应分段。
- **1080p cairo 渲染速度**：每帧约 0.05–0.5 秒，取决于场景复杂度；177 秒、30 fps 的片子用 5 个进程约 5–20 分钟。

## 音频
- **低音轰鸣在手机 / 笔记本上听不到，或一下砸出来吓人**：小扬声器基本放不出 100 Hz 以下，只靠 55 Hz 正弦的音效等于没声音；要保留 200–900 Hz 的谐波（带限锯齿 + 低通）。方波 + tanh 能听到但刺耳，起音 0.03 秒像惊吓；用 0.2–0.3 秒正弦平方起音。`braam()` 已按此实现。
- **Karplus-Strong `pluck` 音高不准**：延迟线长度取整，实测 440 Hz 出来 438.4 Hz（−6.5 音分）、1568 Hz 偏 +6 音分，和弦会莫名“拍”。音程、律制、拍音演示用 `pluck_exact` / `organ` / `additive`。
- **`pad` / `choir` 传了 Hz（`pad([mtof(53), ...])`）**：它们收的是 MIDI 音符号，内部会再 `mtof` 一次，频率高到混叠，`pad` 变成一段持续几十秒的刺耳高频正弦（例如固定在 3.5 kHz），`choir` 则只剩气声、没有音高。直接传 `[53, 60, 65]`；现在两者遇到大于 127 的值会报错。交付前对整条音轨按秒查 2.5 kHz 以上是否有持续数秒、频率不变的窄带峰。
- **持续的刺耳高音肉眼看电平查不出来**：逐秒 RMS 看不出某个 3 kHz 正弦一直在响。把音效 / 配乐总线单独存成 wav，跑 `vk_scan.py whine`，它报出持续 ≥3 秒、频率稳定、能量占比高的 2.5 kHz 以上窄带；持续性的音效（灯光、嗡鸣、氛围）做低通（≤2.5 kHz）和淡入淡出。
- **不同长度的数组相加报广播错误**：用 `P(a, b, ...)`。`noise(L / SR) * env(L / SR)` 这类按秒数生成的数组可能和 `x[i:i + L]` 差一个采样，往固定长度的切片里累加时直接用采样数生成（`rng.standard_normal(L) * np.exp(-np.arange(L) / SR * k)`）。
- **混音峰值超过 1**：不要整体除以峰值（会把全片压小），用 `master` 或 `tanh` 软削波；最终跑 `vk_finalize`（loudnorm −14 LUFS）。
- **模拟里的咔哒声太密，变成白噪声**：增益按 1/√密度缩放（`click_rain` 已实现）。
- **agent 无法试听**：用每秒电平数据做检查，并如实告知。
- **在混音上先手动把音乐压低（某句沉重的台词），再过 `level`，压低的地方又被拉回来了**：`level` 就是把安静段抬高。顺序改为：音乐先 `level`，再 `automate` 压低，最后和音效混合。
- **`np.convolve` 做几秒长的滑动平均（48 kHz 下窗口十几万点）要跑好几分钟**：用 `vk_audio.movavg`（cumsum，O(n)）。
- **整片动态太大（安静段比高潮低 20 dB 以上，手机外放听不见）**：混音后、`master` 前过一遍 `vk_audio.level(mix)`（2.5 秒窗口的慢速电平拉平，ratio 0.5 约把差距减半），再用 `vk_scan levels` 看逐秒电平。
- **Windows 中文系统 print 中文报错或乱码**：控制台是 GBK，运行前设 `PYTHONIOENCODING=utf-8`；脚本读写源码时 `open(..., encoding='utf-8')`。
